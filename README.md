# Эмулятор командной оболочки UNIX на C++ для Windows

Практическая работа №1 по дисциплине «Конфигурационное управление».

## Общее описание

Программа `emulator` — консольное приложение (CLI), которое имитирует работу
в командной строке UNIX-подобной ОС (bash). Эмулятор работает поверх
виртуальной файловой системы (VFS), которая загружается из XML-файла
целиком в память (библиотека [pugixml](https://pugixml.org/)). Все операции
с VFS, включая копирование, выполняются только в памяти — исходный XML-файл
никогда не изменяется.

Возможности по этапам:

| Этап | Название               | Что реализовано                                                        |
|------|------------------------|------------------------------------------------------------------------|
| 1    | REPL                   | Приглашение `username@username:~$`, разбор команд, `exit`, `command not found` |
| 2    | Конфигурация           | Параметры командной строки, отладочный вывод, стартовый скрипт         |
| 3    | VFS                    | Загрузка VFS из XML, проверка корневого элемента, обработка ошибок     |
| 4    | Основные команды       | `ls` (флаги `-l`, `-h`, `-a`), `cd`, `who`, `rev`                      |
| 5    | Дополнительные команды | Команда `cp` (изменяет VFS только в памяти)                            |

## Требования

1. ОС: Windows 10/11 (используется `windows.h`).
2. Компилятор с поддержкой C++17: MSVC (Visual Studio) или MinGW-w64 (`g++`).
3. Библиотека pugixml (`pugixml.hpp`, `pugixml.cpp`) — исходники можно
   положить рядом с `emulator.cpp` или подключить через vcpkg.
4. Консоль с поддержкой кириллицы (в программе вызывается
   `setlocale(LC_ALL, "Russian")`).

## Структура репозитория

```
fluffy-guide/
├── emulator.cpp   — вся реализация: REPL, загрузка VFS, команды
├── vfs.xml        — пример образа VFS
├── script.txt     — пример стартового скрипта
└── README.md
```

Файлы `vfs.xml` и `script.txt` — примеры, имена можно выбирать любые.

## Сборка и запуск

Сборка (g++, исходники pugixml лежат рядом):

```bat
g++ -std=c++17 -O2 emulator.cpp pugixml.cpp -o emulator.exe
```

Сборка (MSVC, «Командная строка разработчика»):

```bat
cl /std:c++17 /EHsc /utf-8 emulator.cpp pugixml.cpp
```

Запуск:

```bat
emulator.exe <путь_к_VFS.xml> <путь_к_стартовому_скрипту>
```

Пример:

```bat
emulator.exe vfs.xml script.txt
```

## Этап 1. REPL

Минимальный прототип с диалогом с пользователем.

**Приглашение к вводу** строится из имени пользователя ОС (переменная
окружения `USERNAME`); оно же используется в качестве имени хоста:

```
ivan@ivan:~$
```

**Парсер** читает первое слово строки как команду, остальное — как
аргументы (через `stringstream`). Пустая строка игнорируется.

**Команды:**

```
exit [код]  — завершает работу эмулятора. С числовым аргументом выводит
              "exit code: <код>". Если аргумент не число —
              bash: exit: <arg> :numeric argument required
<другая>    — bash: <команда с аргументами>: command not found
```

**Функции:**

```
command_prompt()  — выводит приглашение username@username:~$
execute(cmd)      — определяет команду и вызывает её обработчик;
                    возвращает false, если нужно завершить работу
kill(instr)       — обработка exit, включая проверку числового аргумента
not_found(instr)  — сообщение о неизвестной команде
main()            — разбор параметров, загрузка VFS, скрипт, REPL
```

**Пример работы:**

```
To run command as administrator (user "root"), use "sudo <command>".
See "man sudo_root" for details.
ivan@ivan:~$ hello world
bash: hello world: command not found
ivan@ivan:~$ exit abc

bash: exit: abc :numeric argument required
```

## Этап 2. Конфигурация

Эмулятор настраивается через параметры командной строки. При запуске
выводятся значения параметров (отладочный вывод).

**Параметры командной строки** (позиционные, оба обязательны):

| Параметр                 | Описание                                      |
|--------------------------|-----------------------------------------------|
| `<VFS_path>`             | Путь к физическому расположению VFS (XML)     |
| `<startup_script>`       | Путь к стартовому скрипту                     |

Если параметров не два, выводится справка и программа завершается с кодом 1:

```
Usage: emulator.exe <VFS_path> <startup_script>
```

**Отладочный вывод** при запуске:

```
VFS path: vfs.xml
Startup script: script.txt
```

**Стартовый скрипт** — текстовый файл, по одной команде в строке.
Пустые строки и строки-комментарии (первый непробельный символ — `#`)
пропускаются. При выполнении на экран выводятся приглашение, сама команда
и её результат — как будто команды вводит пользователь.

После завершения скрипта эмулятор переходит в интерактивный режим.

**Ошибки в скрипте.** Выполнение скрипта не прерывается: ошибка
учитывается во внутреннем счётчике, а по окончании скрипта выводится
сообщение:

```
В ходе работы программы были обнаружены ошибки
```

Если файл скрипта не найден, программа завершается с кодом 1:

```
Error: cannot open script: nope.txt
```

**Пример скрипта `script.txt`:**

```
# Проверка стартового скрипта
ls
cd home

ls -l
```

## Этап 3. VFS

Подключена виртуальная файловая система.

- Источник VFS — XML-файл. Он читается один раз при старте и целиком
  загружается в дерево в памяти (`xml_document vfs_doc`).
- Содержимое файлов хранится в XML как обычный текст.
- XML-файл не изменяется ни при каких командах.
- Текущий каталог хранится в переменной `current_path` (начальное
  значение — `/`).

**Формат XML:**

```xml
<?xml version="1.0" encoding="UTF-8"?>
<vfs>
  <directory name="home">
    <directory name="docs">
      <file name="todo.txt">Buy milk</file>
    </directory>
    <file name="hello.txt">Hello, world!</file>
    <file name=".hidden">secret</file>
  </directory>
  <file name="motd">Welcome</file>
</vfs>
```

| Элемент                      | Значение                                        |
|------------------------------|-------------------------------------------------|
| `<vfs>`                      | корень VFS (`/`), обязателен                    |
| `<directory name="...">`     | каталог, может содержать `<directory>`, `<file>`|
| `<file name="...">`          | файл, текст элемента — содержимое файла         |

Остальные элементы при поиске и выводе игнорируются.

**Ошибки загрузки VFS** (эмулятор выводит сообщение и завершается с кодом 1):

```
[VFS ERROR] Не получилось открыть или разобрать XML-файл: <путь>
[VFS ERROR] Причина: <описание ошибки от pugixml>
[VFS ERROR] Неправильный корневой элемент.
```

**Функции:**

```
load_vfs(path)            — чтение XML, проверка корневого элемента <vfs>
find_directory(root, path) — поиск каталога по абсолютному пути
find_entry(parent, name)   — поиск файла/каталога по имени внутри каталога
find_entry_by_path(path)   — поиск файла/каталога по пути
find_parent_by_path(path)  — поиск родительского каталога по пути
normalize_path(path)       — приведение пути к абсолютному виду
                             (относительно current_path, "." и ".." учитываются)
```

## Этап 4. Основные команды

`ls` и `cd` работают с VFS, добавлены команды `who` и `rev`.

**Команды:**

```
ls [-l] [-h] [-a]
    Выводит содержимое текущего каталога в порядке следования в XML.
    -l — подробный формат: права, тип/размер, имя.
         Каталог: drwxrwx---  <dir>  имя
         Файл:    -rwxrwx---  размер  имя
    -h — человекочитаемый размер (b, Kb, Mb), используется вместе с -l.
    -a — показывать скрытые файлы (имя начинается с точки).
    Флаги можно объединять: ls -lah.
    Ошибки: ls: invalid argument: <arg>      (аргумент без '-')
            ls: неизвестный флаг: <arg>

cd [путь]
    Меняет текущий каталог. Без аргументов и с "/" — переход в корень.
    Поддерживаются абсолютные и относительные пути и "..".
    Ошибки: cd: каталог не найден: <путь>

who
    Выводит заголовок NAME / LINE / TIME и две строки: root (tty1) и
    текущего пользователя ОС (pts/0) с текущей датой и временем.
    Ошибки: при любом аргументе выводится сообщение о неизвестном флаге.

rev <файл>
    Выводит содержимое файла текущего каталога, развернув его задом наперёд.
    Скрытые файлы (с точкой в начале имени) не обрабатываются.
    Ошибки: Укажите файл
            Файл не найден
```

**Функции:**

```
ls(instr, path)   — листинг каталога, разбор флагов -l, -h, -a
cd(instr, path)   — смена текущего каталога
who(instr)        — информация о пользователях
rev(instr, path)  — разворот содержимого файла
```

**Пример работы** (`emulator.exe vfs.xml script.txt`, интерактивный режим):

```
ivan@ivan:~$ ls
home
motd
ivan@ivan:~$ ls -l
drwxrwx---  <dir>       home
-rwxrwx---           7  motd
ivan@ivan:~$ cd home
ivan@ivan:~$ ls -a
docs
hello.txt
.hidden
ivan@ivan:~$ ls -lh
drwxrwx---  <dir>       docs
-rwxrwx---      13 b  hello.txt
ivan@ivan:~$ rev hello.txt
!dlrow ,olleH
ivan@ivan:~$ cd docs
ivan@ivan:~$ cd ..
ivan@ivan:~$ cd nope
cd: каталог не найден: nope
ivan@ivan:~$ who
NAME	LINE	TIME
root	tty1	2026-10-24 14:30
ivan	pts/0	2026-10-24 14:30
ivan@ivan:~$ rev nope.txt
Файл не найден
```

> Приглашение всегда содержит `~` — текущий каталог в нём не отображается.

## Этап 5. Дополнительные команды

Добавлена команда `cp`, изменяющая состояние VFS. Изменения существуют
только в памяти и пропадают после выхода из эмулятора; XML-файл остаётся
нетронутым.

**Команда:**

```
cp [-r | -R] источник назначение
    Копирует файл или каталог.
    - Если назначение — существующий каталог, объект копируется внутрь него
      под прежним именем.
    - Если назначения нет, создаётся копия с новым именем (родительский
      каталог назначения должен существовать).
    - Каталоги копируются только с флагом -r (рекурсивно, вместе с содержимым).
    - Существующие объекты не перезаписываются.
    Успех:  Скопировано: <источник> -> <назначение>
    Ошибки: cp: неизвестный флаг: <флаг>
            Использование: cp [-r] источник назначение
            cp: источник не найден: <источник>
            cp: пропущена директория (не указан -r): <источник>
            cp: назначение не является директорией: <назначение>
            cp: каталог назначения не найден: <назначение>
            cp: нельзя копировать объект внутрь самого себя
            cp: объект уже существует: <имя>
```

**Функции:**

```
cp(instr)  — разбор флагов и аргументов, проверки, копирование узла
             (xml_node::append_copy — глубокая копия для каталогов)
```

**Пример работы** (после `cd home`):

```
ivan@ivan:~$ cp hello.txt hello_copy.txt
Скопировано: hello.txt -> hello_copy.txt
ivan@ivan:~$ cp hello.txt docs
Скопировано: hello.txt -> docs
ivan@ivan:~$ cp docs backup
cp: пропущена директория (не указан -r): docs
ivan@ivan:~$ cp -r docs backup
Скопировано: docs -> backup
ivan@ivan:~$ cp -r docs docs/inner
cp: нельзя копировать объект внутрь самого себя
ivan@ivan:~$ cp hello.txt hello_copy.txt
cp: объект уже существует: hello_copy.txt
ivan@ivan:~$ cp nope.txt backup
cp: источник не найден: nope.txt
ivan@ivan:~$ exit
exit code: 0
```

## Известные ограничения

- `ls` показывает только текущий каталог (пути в аргументах не поддерживаются)
  и не сортирует имена.
- `cd` понимает `..` только как единственный аргумент (`cd ..`), но не как
  часть пути (`cd ../docs`); `.` и `~` не поддерживаются.
- `rev` работает только с файлами текущего каталога, разворачивает
  содержимое побайтово (корректно для ASCII и однобайтовых кодировок) и
  обрабатывает один файл.
- `exit` в стартовом скрипте не завершает программу — после скрипта
  эмулятор продолжает работу в интерактивном режиме. Код возврата процесса
  не зависит от аргумента `exit`.
- Комментарии в скрипте поддерживаются только в виде отдельной строки с `#`.
- Приглашение не отражает текущий каталог VFS.
